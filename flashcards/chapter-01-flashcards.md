## Chapter 1: vSphere 8 Architecture and ESXi Installation — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | ESXi 8 minimum RAM requirement? | 8 GB RAM minimum to install/run ESXi (production hosts need far more). Also requires minimum 2 CPU cores and a 64-bit x86 CPU with NX/XD bit enabled. Exam tip: pre-2016-era CPUs are no longer supported in vSphere 8. |
| 2 | Minimum size for ESXi 8 boot USB/SD device? | 8 GB minimum for the boot bank only. A SEPARATE persistent storage device of at least 32 GB (128 GB+ SSD/NVMe recommended) is required for the ESX-OSData partition. Exam tip: SD/USB alone can no longer host OSData since ESXi 7.0 U3. |
| 3 | Recommended size/type for the ESX-OSData partition in ESXi 8? | 32 GB minimum, 128 GB+ recommended; SSD or NVMe preferred for performance, especially with vSAN or heavy logging. Exam tip: this partition holds /scratch, the VMFS-L locker, and core dumps. |
| 4 | vSphere Client vs ESXi Host Client — when to use each? | vSphere Client (HTML5, connects to vCenter): manages multiple hosts/clusters, DRS, HA, vMotion. Host Client (https://<host-ip>/ui): manages a single standalone host, used when vCenter is unavailable or for initial setup. Exam tip: Host Client cannot perform vMotion between hosts or manage clusters. |
| 5 | Auto Deploy: Stateless vs Stateless Caching vs Stateful Install | Stateless: image pulled fresh from Auto Deploy server every boot, no local storage used. Stateless Caching: image cached to local disk as fallback if the Auto Deploy server is unreachable. Stateful Install: image installed permanently to disk on first PXE boot, then behaves like a normal install. Exam tip: only Stateless requires zero local storage. |
| 6 | Kickstart (ks.cfg) file location boot options | ks=cdrom, ks=usb, ks=nfs://server/path/ks.cfg, ks=http://server/path, ks=ftp://server/path. Exam tip: the 'ks=' option is passed at the ESXi installer boot prompt to trigger scripted install. |
| 7 | ESXi evaluation mode: duration and expiration behavior? | 60-day full-feature evaluation from first boot. At expiration, running VMs continue running, but no new VM can be powered on until a valid license key is assigned. Exam tip: assign the license before the 60-day window closes. |
| 8 | vSphere per-CPU core license capacity (7 U3+/8)? | Each per-CPU license covers up to 32 cores. CPUs with more than 32 cores require additional license units to fully license that CPU. Exam tip: always check physical core count vs. license capacity during host sizing. |
| 9 | DCUI (Direct Console User Interface) — primary use cases? | Set root password, configure the management network (IP/VLAN), restart management network/agents, view system logs, enable/disable Lockdown Mode. Exam tip: DCUI does NOT provide full NTP configuration or licensing — use Host Client for those. |
| 10 | Where to verify ESXi 8 hardware compatibility before purchase/deployment? | VMware Compatibility Guide (VCG) at vmware.com/compatibility — validates server model, CPU family, storage controller, and NIC support. Exam tip: unsupported/older CPUs cause installation failures on ESXi 8. |
| 11 | NTP vs PTP time synchronization in vSphere 8 | NTP: software-based, millisecond accuracy, UDP port 123, standard for most clusters. PTP (Precision Time Protocol): hardware-assisted, microsecond/nanosecond accuracy, requires supported NIC/hardware clock, can be exposed to VMs via a precision clock device. Exam tip: PTP targets latency-sensitive workloads (trading, telco). |
| 12 | esxcli commands to view/set NTP on an ESXi host | esxcli system ntp set --server=<ntp-server> esxcli system ntp set --enabled=true esxcli system ntp get (verify). Exam tip: clock drift across hosts breaks vMotion, HA reference checks, and certificate validity cluster-wide. |
